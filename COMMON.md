# Trade Signal

## Что делает приложение
Приложение запускает Telegram-бота для анализа forex-пар через iTick.

Основной сценарий такой:
- пользователь выбирает пару в формате `GB/EURUSD`;
- выбирает таймфрейм;
- выбирает, какие сигналы отслеживать;
- бот периодически запрашивает свечи из iTick;
- по закрытым свечам считает индикаторы и определяет пересечения;
- по запросу показывает краткий срез данных или отправляет AI-отчёт через OpenRouter.

Точка входа в приложение: `main.py`.

Запуск:

```bash
uv run main.py
```

## Основные модули
- `main.py` и `internal/main.py` — запуск Telegram-бота.
- `internal/config.py` — чтение настроек из `.env`.
- `internal/forex/itick.py` — клиент iTick, загрузка свечей, фильтрация закрытых баров, расчёт индикаторов.
- `internal/forex/signal.py` — логика определения сигналов по двум последним доступным барам.
- `internal/forex/main.py` — единый пайплайн анализа, который используют бот и мониторинг.
- `internal/telegram/main.py` — диалог с пользователем в Telegram.
- `internal/telegram/monitor_job.py` — фоновый опрос и отправка уведомлений.
- `internal/telegram/answer.py` — форматирование ответов для Telegram.
- `internal/ai/main.py` — запрос в OpenRouter.
- `internal/ai/ta_ai.py` — подготовка CSV-блока с индикаторами для AI-анализа.

## Конфигурация
Используются переменные:
- `ITICK_ENVIRONMENT` — `DEV` или `PROD`.
- `BOT_API_KEY` — токен Telegram-бота.
- `TOKEN_ENCRYPTION_SECRET` — секрет для шифрования пользовательских токенов iTick в БД.
- `BOT_ACCESS_TOKENS` — через запятую, токены для `/auth`, авторизация по user_id сохраняется в БД.
- `SQLITE_DB_PATH` — путь к SQLite (по умолчанию `./data/trade_signal.db`).
- `open_router` — ключ OpenRouter для AI-отчёта.
- `LOG_LEVEL` — сейчас хранится в настройках, но в логике почти не используется.

Базовые URL iTick:
- `DEV` -> `https://api-free.itick.org/forex`
- `PROD` -> `https://api0.itick.org/forex`

## Как работает анализ
Функция `internal/forex/main.py:main()` принимает:
- `code`, например `GB/GBPJPY`;
- `k_type`, например `1`, `3`, `5`;
- опционально `client`.

Пайплайн:
1. Разбивает `code` на `region` и `symbol`.
2. Через `Itick.connect()` делает проверочный запрос в iTick.
3. Через `fetch_candles()` получает до `500` свечей.
4. Оставляет только закрытые бары по времени открытия и `k_type`.
5. Собирает `DataFrame` с колонками `time`, `open`, `high`, `low`, `close`, `volume`.
6. Считает индикаторы:
   - `EMA_4`
   - `EMA_8`
   - `EMA_16`
   - `EMA_75`
   - `RSI_15`
   - `weighted_close`
   - `EMA_4_WC`
   - `EMA_8_WC`
7. Проверяет сигналы на двух последних валидных барах.
8. Отдельно считает выбранные фильтры.
8. Возвращает:
   - `indicator`
   - `signals`
   - `filters`
   - `fresh_candles`
   - `data_frame`

При прямом запуске `internal/forex/main.py` просто печатается итоговый `DataFrame`.

## Какие сигналы поддерживаются
Сейчас в проекте три группы сигналов:
- `ema_4_8`
- `ema_8_16`
- `ema_wc_4_8`

Для каждой группы вычисляется:
- `bullish`
- `bearish`

Итоговый объект `signals` также содержит `has_some_signal`.

Логика одна и та же:
- берутся две последние строки после удаления `NaN` по нужным колонкам;
- если быстрая линия пересекла медленную снизу вверх, это `bullish`;
- если сверху вниз, это `bearish`;
- если на границе одновременно подходят оба варианта, направление уточняется через `drift`.

## Какие фильтры поддерживаются
Сейчас в проекте доступны два фильтра:
- `ema_75`
- `rsi_15`

Для каждого фильтра вычисляется:
- `confirm`
- `block`

Текущая интерпретация:
- `EMA 75`: `close > EMA_75` -> `confirm`, `close < EMA_75` -> `block`;
- `RSI 15`: `RSI_15 > 50` -> `confirm`, `RSI_15 < 50` -> `block`;
- при равенстве или отсутствии данных фильтр остаётся нейтральным.

## Как работает Telegram-бот
- `/auth <token>` — авторизация по токену из `BOT_ACCESS_TOKENS`, user_id сохраняется в БД.
- `/itick` — сохранить пользовательский токен iTick (обязательно, иначе ошибка).
- `/signals` — управление пресетами сигналов (CRUD, без запуска мониторинга). Пресет: имя → TF → сигналы (≥1) → фильтры (0..N). Лимит 3 пресета на пользователя.
- `/start`:
  1) ввод пары (формат `GB/XXXXXX`);
  2) если нет пресетов — сообщение «У вас еще нет настроенных сигналов, настройте их в главном меню бота»;
  3) если есть — выбор одного или нескольких пресетов; запуск мониторинга по каждому пресету (с его TF/сигналами/фильтрами).
- Мониторинг: мгновенный первый прогон, далее каждые 60 секунд; уведомление только на фронте появления сигнала (False->True), с учётом фильтров; в сообщении имя пресета и пара.

Во время мониторинга доступны кнопки:
- `⏹️ Остановить`
- `📊 Запросить данные`
- `🤖 Анализ ИИ`

## Что отправляет бот
`📊 Запросить данные`:
- текущие сигналы;
- последние 2 закрытых бара;
- EMA и `close` в компактном виде.

`🤖 Анализ ИИ`:
- берёт последние `55` строк `DataFrame`;
- сериализует их в CSV;
- отправляет в OpenRouter вместе с системным промптом;
- возвращает текстовый TA-отчёт в заданном шаблоне.

Если iTick недоступен или токен истёк, поднимается `ItickUnavailableError`, мониторинг останавливается, пользователю отправляется сообщение об ошибке.

## Формат данных iTick
Ожидается массив `data`, где каждая свеча содержит:
- `t` — время открытия бара в Unix ms;
- `o` — open;
- `h` — high;
- `l` — low;
- `c` — close;
- `v` — volume.

Закрытие бара определяется локально, а не приходит отдельным флагом от API.
