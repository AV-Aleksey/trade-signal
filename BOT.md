# Telegram-бот (trade-signal)

Модуль: [`internal/telegram_bot.py`](internal/telegram_bot.py). Один запрос к логике сигнала из [`internal/main.py`](internal/main.py): свечи iTick → EMA → текст сигнала и превью DataFrame.

Подробности про iTick, переменные окружения и формат свечей — в [`COMMON.md`](COMMON.md).

---

## Переменные окружения

| Переменная | Назначение |
|------------|------------|
| `BOT_API_KEY` | Токен бота от [@BotFather](https://t.me/BotFather), обязателен |
| `ITICK_ENVIRONMENT` | `DEV` или `PROD` — базовый URL Forex API (см. COMMON.md) |
| `TOKEN_ENCRYPTION_SECRET` | Секрет для шифрования токенов iTick в БД |
| `BOT_ACCESS_TOKENS` | Через запятую: список токенов доступа к боту (для /auth) |
| `SQLITE_DB_PATH` | Путь к SQLite (по умолчанию `./data/trade_signal.db`) |
| `LOG_LEVEL` | По умолчанию `INFO` |

Файл `.env` в корне проекта подхватывается через [`internal/config.py`](internal/config.py).

---

## Запуск

Из корня репозитория (нужны установленные зависимости проекта: `python-telegram-bot`, `pandas`, и т.д.):

```bash
python -m internal.telegram_bot
```

## Поведение для пользователя

1. Команда **`/auth <token>`** — разовая авторизация пользователя (токен из `BOT_ACCESS_TOKENS`, успешный `user_id` запоминается в БД).
2. Команда **`/start`** — бот просит ввести валютную пару (6 букв, напр. `GBPJPY` → `GB/GBPJPY`).
2. Если для пользователя нет пресетов сигналов — выводится подсказка настроить их через **`/signals`**.
3. Если пресеты есть — бот показывает список пресетов для выбора (мультивыбор, максимум 3 пресета сохранено).
4. При подтверждении запускается мониторинг по выбранным пресетам (каждый пресет со своим TF/сигналами/фильтрами).

**Обозначение инструмента в терминах рынка:** полный вид вида **`GB/GBPJPY`** — это **`GB/`** (код рынка в iTick, здесь совпадает с регионом по умолчанию) и **`XXXXXX`** — 6 букв пары. В чат бот запрашивает только код пары (6 букв); регион в коде фиксирован.
4. В чат приходят три сообщения:
   - блок **Parameters** (инструмент, интервал `1m`, timeout);
   - блок **Signal** («EMA 4 пересекает EMA 8» или «Нет сигнала»);
   - заголовок **DataFrame** и inline-кнопка **«Показать DataFrame»** — по нажатию отправляется превью (хвост таблицы в `<pre>`), длинный вывод режется на части.

Повторный **`/start`** снова включает режим ожидания пары.

Сообщения вне сценария «ожидаем пару после start» игнорируются обработчиком пары.

### Настройка сигналов (глобально)
- Команда **`/signals`** — управление пресетами (только CRUD, без запуска мониторинга).
- Создание пресета: имя → выбор TF → выбор сигналов (≥1) → выбор фильтров (0..N). Лимит 3 пресета на пользователя.
- Пресеты хранятся в SQLite и содержат списки id сигналов/фильтров.
- Доступ к `/signals` только для авторизованных (после `/auth`).

### Мониторинг (фоновый опрос)

### Мониторинг (фоновый опрос)

Пока активен режим опроса свечей, в чат **ничего не отправляется**, если на очередном закрытом баре **нет** торгового сигнала. Сообщение пользователю — **только** при срабатывании условия сигнала (например пересечение EMA по правилам [`internal/itick.py`](internal/itick.py)). Ошибки API и обрыв связи обрабатываются отдельно (не считаются «отсутствием сигнала»).

---

## Ошибки

При исключении из скрипта (сеть, API, нет закрытых свечей и т.д.) пользователь получает текст вида `Script execution failed: …`.
Отдельно для iTick: «Сервис временно недоступен, возможно просрочен токен или превышен лимит запросов в минуту».

---

## Зависимости от кода сигнала

- Инструмент в ответе бота — **код пары** (6 букв); префикс рынка в UI не выводится (регион задан в `main`).
- Сигнал: пересечение **EMA 4** и **EMA 8** на двух последних **закрытых** барах (логика в [`internal/itick.py`](internal/itick.py)).
